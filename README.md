# 小米路由器 R3Gv2 PPPoE 拨号失败（错误 1603 / 678）故障记录

一台小米 R3Gv2 做 PPPoE 拨号时**稳定失败**，路由器后台报：

```
认证失败（用户密码异常导致）(678)      ← 后台错误码 1603
```

而同一条入户线、同一个账号，**用电脑直拨、用 Radxa A7A 拨号都能一次成功**。

本仓库记录完整的排查过程、**已经实测排除的项**、以及按优先级排列的诊断方案 ——
希望能帮到遇到同样问题的人。

> 记录时间：2026-09-14
> 线路：中国联通（安徽）· 接入方式：PPPoE（光猫桥接）· 获得的是 CGNAT 地址（`100.64.0.0/10`）

---

## 一、现象

| 项 | 值 |
|---|---|
| 设备 | 小米路由器 R3Gv2 |
| 后台错误 | `1603`，文案「认证失败（用户密码异常导致）(678)」 |
| 复现性 | 稳定复现；**重启、改密码、重置拨号均无效** |
| 设备局域网地址 | `192.168.10.1` |

---

## 二、关键前提：同样的条件在别的设备上是通的

| 设备 | 拨号方式 | 结果 |
|---|---|---|
| 电脑（Windows 自带宽带连接） | PPPoE 直拨 | ✅ 拿到 `100.75.2.99/32` |
| Radxa Cubie A7A（Debian + pppd） | PPPoE 直拨 | ✅ 拿到 `100.75.18.191/32`，出口 `36.33.45.68` |

**→ 入户线、光猫、账号凭据、局端放行全部正常。问题被隔离在 R3Gv2 自身。**

这条前提非常关键：它把"线路坏了 / 账号错了"这两大类可能性直接排除，
省掉了大量无谓的排查。

---

## 三、已实测排除的项

### 3.1 「局端按 MAC 放行，必须克隆 MAC」——**本线路不成立**

网上（包括一些教程）普遍说：运营商绑 MAC，所以路由器必须克隆已登记的 MAC。
我们做了一个**干净的对照实验 —— 只改 WAN MAC，其他参数一律不动**：

| WAN MAC | 结果 |
|---|---|
| `b0:25:aa:7f:0c:2d`（电脑有线网卡的 MAC） | ✅ 拨通 `100.75.18.191/32` |
| `02:00:00:00:00:01`（本地管理地址，**明显未登记**） | ✅ **照样拨通** `100.75.73.160/32`，CHAP `Authentication success,Welcome!` |

**结论：本线路的局端不做 MAC 绑定，任意 MAC 都能拨通。**

→ 所以 R3Gv2 的 1603 **不是 MAC 问题**，"MAC 没克隆对"这条假设被排除。

> 注意：这只证明**本线路**不绑 MAC。不同运营商/地区策略不同，别人仍可能需要克隆。

### 3.2 「拨号抑制窗口」——**不是主要矛盾**

运营商 BRAS 对频繁失败拨号确实有抑制，但实测：停掉 pppd 后**静置 20~45 秒**再拨，
**一次就通**，并没有撞上任何抑制窗口。

→ 说明"频繁拨号被拉黑"在本案里也不是主因。

---

## 四、错误码辨析（重要，别被文案带偏）

小米把两个错误码混在一起报了。它们的真实含义完全不同：

| 错误码 | 真实含义 | 常见原因 |
|---|---|---|
| **678**（XP）/ **651**（Win7+） | 远程计算机**无响应** —— 报文发出去了，对端没回 | 物理层/链路层不通、**服务商绑定 MAC**、局端设备异常 |
| **691** | **认证被拒** —— 请求到了 BRAS，被拒绝 | 账号密码错、**MAC 绑定冲突**、**旧会话未释放**、欠费停机 |

来源：[TP-LINK 官方：Windows 各操作系统常见 PPPoE 拨号错误代码说明](https://smb.tp-link.com.cn/service/detail_article_406.html)

**关键**：TP-LINK 官方文档在 **678/651** 这一栏里就明确写了
「**服务商绑定 MAC 地址。只有绑定的电脑可以拨号上网**」——
也就是说 MAC 不对时，报的可能就是"无响应"或"认证失败"，而不是什么密码问题。

（当然，本案已实测排除 MAC 因素，见 3.1。）

## 五、诊断方案（按优先级，成本从低到高）

### 方案 1｜账号密码的隐藏字符 ← 先做这个

**为什么排第一**：同样的凭据在别的设备上一直能通过，而 R3Gv2 报的恰恰是"用户密码异常"。

- **不要复制粘贴**，在路由器后台**手动逐字符重输**账号和密码
- 注意**输入法状态**（全角 / 半角）、**前后空格**
- 确认账号后缀完整（部分运营商要求 `账号@域名` 格式）

来源：[php.cn：691 排查（密码末尾空格 / 输入法 / @ 符号）](https://www.php.cn/faq/2723331.html)、
[爱拨测：小米路由器 691 解析](https://www.aiboce.com/ask/383292.html)

### 方案 2｜清掉 BRAS 上的旧会话（拔电静置 + 冷启）

**原理**：上一次非正常断线，BRAS 没收到下线通知，账号仍挂在"在线表"里，
再拨就被当成**重复拨号**而拒绝。

- 路由器**拔电 10 分钟以上**（不是软重启）
- 期间确认**没有别的设备用同一账号在拨**
- 上电后**只拨一次**，不要连续重试

来源：[TP-LINK 官方](https://smb.tp-link.com.cn/service/detail_article_406.html) 691 项下第二条；
[百度百科「错误 691」](https://baike.baidu.com/item/错误691/5038085) 里的运营商真实案例
（「用户账号在线，踢下该用户账号后，用户正常」）

### 方案 3｜光猫侧冲突排查

**原理**：如果光猫自己还在拨号（路由模式没真正关掉），路由器再拨就是**并发拨号** → 被拒。

- 确认光猫是**纯桥接**，且光猫自己没在拨号
- 确认没有第二台设备（旧路由器等）也在用这个账号拨

来源：[爱拨测：小米路由器 691 解析](https://www.aiboce.com/ask/383292.html)、
[百度贴吧：创维光猫改桥接后路由器拨号 691](https://tieba.baidu.com/p/8867487612)
（「账号密码正确但改密码重启均无效」—— 与本例高度相似）

### 方案 4｜小米固件的 PPPoE 会话保持缺陷

有资料指出：**部分小米路由器固件版本存在「PPPoE 会话保持逻辑缺陷，
重启后未释放旧会话，导致新拨号被拒」**。

- 升级到最新稳定版固件再试
- 仍不行 → 刷 **OpenWrt**（R3Gv2 是热门机型，社区支持成熟），彻底换掉厂商的拨号实现

来源：[爱拨测：小米路由器 691 解析](https://www.aiboce.com/ask/383292.html)

> ⚠️ 这条我们**尚未在本机验证**，仅作为线索。

### 方案 5｜旁路抓 PPPoE 握手（终极证据，需要硬件）

在光猫和路由器之间插一个观察点，直接看字节流：

- 端口镜像交换机（最优），或给一台 Linux 机器加 USB 网卡做透明桥，或老式 hub

```bash
tcpdump -i <if> -w pppoe.pcap 'pppoed or pppoes'
```

| 抓到的现象 | 结论 |
|---|---|
| 只有 PADI，没有 PADO | 二层/BRAS 层不通 → MAC 被拒 或 速率协商问题 |
| 有 PADO/PADS，但 CHAP 被拒 | 认证问题 → 账号 / 密码 / 绑定 |
| PADS 之后立刻收到 PADT | 会话被踢 → 重复拨号 / MAC 冲突 |
| 完全没有 PADI 发出 | 路由器 WAN 口没发包 → 硬件 / 驱动 / 固件问题 |

来源：[tsight.io：PPPoE 底层真相与排障指南](https://tsight.io/articles/14563836)

### 方案 6｜交叉替换（二分定位）

拿"已知能拨通"的设备当参照物，一次只换一个变量：

- 让 R3Gv2 借用能拨通那台设备的 MAC → 看是否变化
- 反过来，让能拨通那台设备用 R3Gv2 的 MAC → 看是否变化

| 前者 | 后者 | 结论 |
|---|---|---|
| 通 | — | MAC 相关（但本案已排除） |
| 不通 | 不通 | 那个 MAC 被局端拒了 |
| 不通 | 通 | MAC 无关，问题在 R3Gv2 固件/硬件 |

## 环境参考

同环境下另一台设备（Radxa Cubie A7A）的可用拨号配置：

```bash
# 千兆网口 RGMII tx-delay 必须先修正（出厂值 12 会发帧损坏，PPPoE 连发现阶段都过不去）
echo 9 > /sys/class/net/end0/device/tx_delay

nmcli device set end0 managed no
modprobe pppoe            # 会带上 ppp_generic / pppox
pppd plugin pppoe.so end0 \
     user <宽带账号> password <密码> \
     mtu 1480 mru 1480 noauth defaultroute usepeerdns \
     logfile /var/log/ppp.log &
```

详见 [radxa_utlra 的 A7A 路由器文档](https://github.com/lilyco-42/radxa_utlra/blob/main/docs/a7a-router-mode.md)。
